# v0.3.0：第三版，真机语音与食堂反馈闭环

发布日期：2026-11-18。前两版为 v0.1.0、v0.2.0。本版是当前手头 X2 的纯语音及食堂记录复现基线，不代表全部赛事任务、表情动作或容器运行已经验收。

## 相比第二版

- Mini 保持为 doubao-seed-2-0-mini-260428；优化回答与首答连接复用，首次主动招呼先回应再询问状态，后续叫名字保留会话。
- 收音期间上传 ASR，支持可选缺 END 停收恢复及灵犀热词；保留诊断统计，避免把恢复片段当作正常完整片段。
- 播音采用约200ms有界提前发送，保留每轮 token、原PCM格式及焦点释放，增加发送落后统计。用户更新后确认本轮效果非常不错。
- 食堂意见在明确确认后保存；修复 CLI 指定路径被统一配置过滤的问题。“对的，要记录”可确认，否定、取消和带修改的意见不会误提交旧草稿。
- Agent 和 Windows 网页入口统一使用 data/dining_feedback.jsonl；用户确认记录表实时更新，旧数据保留。网页通过当前IP的SSH隧道查看。
- 补齐本地.env自动读取、锁定离线依赖、动态IP、更新与恢复步骤；VERSION和离线清单记录交付版本及可用的Git来源信息。

## 验证事实

本版基于已实测的 AimDK v1.0.0-ga424add、Ubuntu22.04/aarch64、Python3.10.12、ROS Humble。机器人依赖及接口字段预检通过，麦克风、ASR、Mini、TTS、扬声器、焦点释放和食堂记录网页闭环已取得实机证据/用户确认。当前相关离线回归164项通过，详见[调查及复测记录](../2026-11-18-playback-and-feedback-path.md)。

用户没有提供最后一轮的完整耗时日志或新增条目计数，因此不补造延迟或记录数；早期4.5秒等指标保留在历史文档，不代表本版速度。不能宣称所有条件下无断续或稳定低于2秒。

## 完整复现

1. 在开发电脑克隆仓库并执行 git checkout --detach v0.3.0，使用自己的Python和Git环境。
2. 按[新电脑指南](../reproduce-on-x2.md)下载锁定依赖并构建 ZIP。Git标签源码自带版本，GitHub源码压缩包无.git时清单的提交号可为空；构建清单另列每个源码及依赖摘要。
3. 当前IP连接PC2，上传并解压ZIP，单独准备自己的.env，加载AimDK并预检。ZIP不包含凭据、录音、反馈历史或机器人SDK。
4. 核对 only_voice 实际状态，再使用指南的纯语音命令；查看食堂反馈时在Windows运行仓库根目录 open_dining_dashboard.cmd，Agent和网页必须读取同一文件。
5. 按[连续对话步骤](../voice-dialogue-acceptance.md)与[环节四步骤](../stage4-dining-feedback.md)复测，保存版本、输入、转写、播报及新记录结果。

本次发布整理文档和交付清单，不修改已确认的对话业务、模型或声音。机器人上的已验证程序不会被Git推送自动更新；仅为了文档升级不必立即重新部署。
