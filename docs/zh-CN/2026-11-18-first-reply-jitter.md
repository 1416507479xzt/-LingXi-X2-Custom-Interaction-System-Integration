# 只优化首答延迟波动：连接保温与分段计时

> 历史联调记录：保留当时问题、命令和结果。第三版当前状态见[验收汇总](aimdk-v1-robot-audio.md)，实际部署请使用[当前复现指南](reproduce-on-x2.md)。

## 用户范围与确认

用户确认20:52六条回答均完整播出。随后明确要求“只优化一下首答延迟波动，其他的不用了”。本次不改提示词、回答长度、药品资料、提醒时间、业务状态、模型型号、TTS语速或VAD停收等待，也不引入重复并发推理、缓存固定答案或提前播放未校验文字。

## 原有瓶颈与改动

原来已使用httpx长连接池，在同步及开始录音时预连接，普通预连接最小间隔60秒。只凭HTTP响应时间，无法判断某轮慢是重新建连接还是连接复用后仍有链路/云端处理等待。

- 活跃Agent启动LLM连接维护任务。每5秒检查，距离最近正常请求完成或预连接成功至少20秒、且没有模型请求进行中时，尝试一次HEAD保温；这不是后台模型生成，不提交对话内容。
- 预连接并发用锁合并，检查时间在锁内重新核对，避免同一时刻重复HEAD。单次HEAD加总预算1秒；连接、读写等HTTP超时各1秒，总预算优先。失败不更新成功时间，后台维护失败只记DEBUG，保留下一轮正常POST路径。
- 不等待后台HEAD才能发正常模型请求；已在途HEAD可能与随后开始的POST短暂重叠，仍使用原最大2条HTTP连接。维护不会因为上一轮变慢而对用户请求额外重试。
- 程序关闭时取消并等待维护任务；流式生成器关闭/取消时释放底层响应并复原活跃请求计数，避免占着连接影响下一轮。
- 增加TCP/TLS、HTTP响应头及首字分段日志。trace只提取事件时间，不打印事件info、Authorization、Key或请求正文。支持直连及代理TLS事件。new_connection=False表示该次未观察到建连事件，不是对整个网络健康的保证；tcp_ms包含连接调用等待，不能进一步拆成独立DNS耗时。

这是减少可控制的冷连接开销，不是云端延迟上限承诺。模型输入、温度、thinking设置、正常推理超时及既有思考参数兼容重试策略都保持原状。

实现依据：[HTTPCore trace扩展](https://www.encode.io/httpcore/extensions/)、[HTTPX分阶段超时](https://www.python-httpx.org/advanced/timeouts/)。本项目锁定httpcore 1.0.6；没有打印trace中的敏感info，也没有新增依赖。

## 验证证据

- 128项语音、传输、业务及新连接测试整套通过。
- 随后给HEAD补充总时限及相应测试，5项连接专项测试全部通过。覆盖并发预连接仅一个HEAD、活跃模型请求不新增HEAD、流取消释放、失败后下一次维护恢复、关闭取消、总时限和日志不泄露trace内容。其余生产逻辑未在此后更改。
- 现有真实HTTP测试验证两轮POST共用一个连接，仍禁用thinking；无关HTTP400不增加重试。
- 开发电脑真实Mini短文本连接探针：先HEAD预连接，TCP约1ms、TLS约84ms、总约258ms；第一轮首字约907ms。空闲25秒期间成功HEAD约88ms，第二轮首字约438ms，两轮POST均未观察到新建TCP/TLS。
- 较早一组短文本探针，在同样没有观察到新建连接时，首字仍有1500ms与437ms的差别。说明本地连接复用不能消除链路及服务端波动，不能把前后数字直接算成该改动的提速百分比。

探针只让模型回复“收到”，没有完整业务提示、ASR、TTS或机器人。上述数字不是降压药回答或真机端到端基准。一次25秒空闲样本不足以证明真机抖动已经解决。

开发电脑可复现（会调用现有账户，两次短文本推理；不连接机器人）：

```powershell
python scripts/check_llm_connection_live.py --live --keepalive --rounds 2 --idle-seconds 25
```

--keepalive启用新维护，不带则保持单次初始预连接，便于对照。脚本位于开发仓库，不在机器人离线包的部署脚本允许清单中；生产Agent的保温和计时已随代码包含在ZIP里，无需在机器人装依赖。

## 真机复测

沿用原上传离线包、PC2解压、source环境、预检和启动命令。回答内容保持原样，仍是Mini、none、实时ASR与1.5秒缺END等待。

1. 唤醒后问“降压药怎么吃”，保留完整日志。
2. 等机器人说完，安静停顿约25秒，再问同一句；重复一至两次。没有重新唤醒或清空会话。
3. 对比每轮ASR、LLM连接计时、回复生成、TTS首包；记录说完到实际听到声音的主观/秒表结果。不能只看最短一轮或忽略失败样本。
4. 如果new_connection=False但headers/first_token仍较慢，说明该轮没有可见冷建连开销，不能再靠缩短VAD、删回答或删除安全校验来掩盖问题；后续按分段证据定位。

新增日志写入既有文件。HEAD最多约每20秒一次（受5秒检查、活跃请求和网络完成时间影响），会增加少量联网请求；正常Agent运行仍消耗CPU/内存，不能说完全零开销。Ctrl+C停止后不再保持后台任务。不修改机器人原生服务和配置。
